# PlugNX Settlement OS Intro Website Design

## Goal
Create a public interactive site that explains PlugNX's foreign-resident PropTech wedge as an AI-native Settlement OS rather than a super app.

## Product thesis
LifeMap is the physical discovery layer. AI Settlement Agent reads visa, job, housing, family, mobility and financial context; composes only the relevant life-event journey; then routes work to execution modules such as moving, storage, cleaning, housing safety, used cars, finance, appraisal and registration. Community Fit is a housing decision variable, not a standalone content feed. Long-term residents progress from rent/jeonse to ownership, financing, appraisal and registration.

## IA
1. Hero: LifeMap + AI Settlement Agent and “not a super app” positioning.
2. Journey Composer: visa × event × housing purpose × priority.
3. Community Fit: explicit resident preferences, not nationality steering.
4. Life Event OS: Work → Home → Move → Mobility → Stay → Finance.
5. Settlement Ladder: Arrival → Stabilize → Upgrade → Settle → Own.
6. Visa/situation journeys.
7. Execution modules: moving, storage, cleaning, temporary stay, used cars.
8. Rent/Jeonse/Buy → value → finance → appraisal → registry.
9. AI architecture: Composer, Evidence, Execution, Next Best Action, Stay/Visa, Outcome.
10. BM: Free Decision → Execution → Sponsor SaaS → Financial Bridge → Infrastructure.
11. PlugNX asset fit and partner CTA.

## Constraints
- Services are not top-level category menus; modules appear as consequences of a selected life event.
- Visa, guarantee and finance outputs are readiness/pre-check, not approval.
- Community recommendations use explicit user preferences; nationality is not used to restrict neighborhoods.
- Demo/sample data is visibly labeled.
- Mobile responsive and keyboard accessible.
- Existing `/lifemap/` remains the detailed product demo.
